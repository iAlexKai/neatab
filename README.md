# Neatab · 最近标签切换与整理

在 Chrome 中获得 Arc 最核心的标签体验：

- **Option + Tab** 在最近使用的 7 个标签页之间切换，按住 Option 选择，松开切换。
- **所有标签页**：一键关闭重复打开的页面，每个地址只保留最近活跃的一个。
- **不活跃标签页**：按 48 小时以上、24–48 小时、12–24 小时、12 小时以内分组，可全部关闭或按组关闭。
- **Command + Shift + C** 复制当前网页的完整链接。
- **自动释放内存**：默认 1 小时未访问的标签页自动释放内存（可选 30 分钟到 6 小时），标签保留，点开时重新加载；关闭时会提示「离开网站？」的页面跳过。

由 Manifest V3 扩展和一个 AppKit 原生辅助程序组成，不需要重启 Chrome。标签整理功能只需要扩展；Option + Tab 和 Command + Shift + C 需要 macOS 辅助程序。

**2.7.0：内存释放更积极。** 默认 1 小时没访问就释放（可选 30 分钟到 6 小时）；Chrome 启动后还没点开的恢复页加载完即释放；macOS 内存紧张时提前释放；是否有未保存内容改为看页面关闭时会不会弹「离开网站？」。需要同时更新扩展和辅助程序。

**2.6.0：不活跃时长只算用电脑的时间。** 锁屏、休眠、超过 10 分钟没有操作、Chrome 退出期间都不计入，过完周末回来，标签页不会全部跳到「48 小时以上」。新增 `idle` 权限，只更新扩展即可。

**2.5.0：预览只盖网页区域。** Option + Tab 的预览和 Chrome 的网页区域对齐，左侧的标签页抽屉、标签栏和地址栏都不会被盖住。需要同时更新扩展和辅助程序。

**2.4.0：「所有标签页」显示 Chrome 标签页分组。** 每个分组显示名称、颜色和标签页数量，和标签栏里的分组对应。新增 `tabGroups` 权限，只更新扩展即可。

**2.3.0：截图存到本机。** 截图按网址保存在 Chrome 的扩展本地存储里，重启 Chrome、重新加载扩展之后，没再点开的标签页也有预览；同一网址的重复页共用一张。只更新扩展即可。

**2.2.0：Option + Tab 全屏预览。** 按住时选中标签页的截图铺满 Chrome 的网页区域，松开后停在截图上，等新页面加载出来再淡出，看起来是直接落到预览页上。需要同时更新扩展和辅助程序。

**2.1.0：自动释放内存**，见下方「自动释放内存」。

**2.0.0：由 Seven 更名为 Neatab**，准备上架 Chrome 网上应用店。辅助程序改为 `Neatab.app`（同时支持 Apple 芯片和 Intel），Native Messaging host 改为 `app.neatab.helper`。从 Seven 升级需要重新安装辅助程序并重新授予辅助功能权限，见下方「从 Seven 升级」。

1.5.0：不活跃标签页分组。1.4.0：关闭重复页。1.3.0：不活跃标签页。1.2.0：复制成功提示。

Arc 官方确认显示最近 **5** 个标签页，默认快捷键是 **Control + Tab**。Neatab 使用 **Option + Tab**，显示最近 **7** 个（含当前页）。原文：[Arc 官方说明](https://resources.arc.net/hc/en-us/articles/25619402657303-How-Do-You-Switch-Between-Tabs-Quickly-on-Arc-Desktop)。这里的「相近上下文」按最近实际访问顺序判断，与 Arc 一样，不分析网页内容的语义相似度。Neatab 与 Arc 及 The Browser Company 没有关联。

## 安装

适用于 macOS 13 或更新版本、Chrome 121 或更新版本。辅助程序为本地临时签名，未经过 Apple 公证。

Neatab 没有上架 Chrome 网上应用店，需要从源码构建安装。

### 从源码安装

1. 克隆本仓库，运行 `npm run build` 和 `npm run package`，解压 `dist/Neatab-macOS.zip`，双击 **安装 Neatab.command**。安装脚本会把文件复制到稳定位置，注册仅供此扩展使用的 Chrome Native Messaging host。
2. 在 Chrome 打开 `chrome://extensions`，开启右上角的**开发者模式**，点击**加载已解压的扩展程序**，选择：

   `~/Library/Application Support/Neatab/neatab-extension`

   文件选择框中可按 `Command + Shift + G` 粘贴上述路径。
3. 点击 Neatab 扩展图标 → **开启辅助功能权限**，在系统设置 → 隐私与安全性 → 辅助功能中允许 **Neatab**。若列表中没有 Neatab，可用 `+` 添加 `~/Applications/Neatab.app`。返回扩展，等待显示「已就绪」。

扩展 ID 由 `manifest.json` 里的公钥固定（`extension-id.txt`）。如果将来发布商店版，商店版的 ID 写进 `store-extension-id.txt`，安装脚本会同时允许两个 ID 连接辅助程序。

### 从 Seven 升级

1. 在 `chrome://extensions` 移除 Seven。
2. 按上面任一方式安装 Neatab 和新辅助程序。
3. 在系统设置的辅助功能列表中用 `−` 移除旧的 Seven，开启 Neatab。
4. 旧文件可手动删除：`~/Applications/Seven.app`、`~/Library/Application Support/Seven`、`~/Library/Application Support/Google/Chrome/NativeMessagingHosts/app.seven.switcher.json`。

首次安装的终端脚本可能要求在系统设置中允许 Terminal 访问文件；辅助功能权限必须由本人手动开启。若系统阻止本地未公证软件运行，请按系统提供的正规批准流程处理。

安装后的文件：

- 辅助程序：`~/Applications/Neatab.app`
- 扩展：`~/Library/Application Support/Neatab/neatab-extension`
- Chrome host 注册：`~/Library/Application Support/Google/Chrome/NativeMessagingHosts/app.neatab.helper.json`

卸载时先在 Chrome 移除扩展，再运行辅助程序安装包中的 **卸载 Neatab.command**。脚本只删除上述 Neatab 文件，系统中的辅助功能授权可手动移除。

已安装旧版时，关闭 Neatab 的连接或暂时停用扩展，运行新版安装脚本，然后在 `chrome://extensions` 点击 Neatab 的重新加载按钮。原生辅助程序也必须更新；若系统要求重新授予辅助功能权限，按系统提示操作。

**更新排查（1.1.1）：**扩展面板会显示扩展和辅助程序各自的版本。辅助程序仍为 1.0.0 时，面板会提示先更新；单独重新加载 extension 不会替换系统中的 `Neatab.app`。若新版仍显示未授权，请在系统设置的辅助功能列表中用 `−` 移除旧 Neatab，再用 `+` 添加 `~/Applications/Neatab.app` 并开启，随后回 Chrome 重新加载 Neatab。当前开发包使用临时签名，系统可能保留上一版的程序身份；仅关闭再开启旧授权项不足以刷新该身份。

## 使用

| 操作 | 行为 |
| --- | --- |
| 按住 Option，按一次 Tab | 选中上一个访问的标签页 |
| 继续按 Tab | 在冻结的最近 7 个列表中向后选择 |
| Option + Shift + Tab | 反向选择，也可直接反向打开 |
| 松开 Option | 激活选中标签页并更新最近顺序 |
| Esc | 取消，停留在原标签页 |
| Enter / 点击卡片 | 确认切换 |
| Option + 左右箭头 | 在已打开的切换器内移动 |
| Command + Shift + C | 复制当前网页的完整链接到剪贴板 |

复制链接保留原地址的查询参数和 `#` 锚点，不附加标题，也不会切换页面。成功写入剪贴板后，Chrome 所在屏幕底部显示「已复制页面链接」，1.2 秒后自动消失；连续复制会刷新同一条提示的停留时间，不叠加、不抢焦点，切到其他应用时隐藏。地址来自按键时对 Chrome 当前活动标签页的查询，而非预览缓存。该组合键在 Neatab 就绪时用于复制链接；普通 Command + C 仍用于复制选中内容。不新增扩展权限。

连续短按 Option + Tab 可以在最后两页之间来回切换。列表按访问时间排列，与标签栏顺序无关。首次加载扩展时会用 Chrome 的 `lastAccessed` 重建最近顺序；之后只按实际激活更新。后台新建的标签页在首次访问前不会插入最近列表。

默认包含此 Chrome 配置文件的所有普通窗口，可在扩展面板改为「当前窗口」。地址栏、普通网页、Chrome 新标签页和 `chrome://` 页面都由原生键盘监听覆盖；这些内部页面可作为目标，但预览显示标题与域名卡片。无痕窗口不参与，切到别的应用不会接管按键。

## 整理标签页

点击扩展图标 → **所有标签页** 或 **不活跃标签页**，打开同一个整理页面，顶部可在两个视图间切换。再次点击会复用已打开的整理页。

### 所有标签页与关闭重复页

按窗口、按标签栏顺序列出所有普通窗口中打开的标签页；属于同一个 Chrome 标签页分组的排在一起，显示分组的名称、颜色和数量，没有命名的显示「未命名分组」。分组只用于显示，关闭规则不受影响。完整地址相同（含查询参数和 `#` 锚点）即为重复；跨窗口的重复也算。

- 每组重复页保留**最近活跃**的一个：正在显示的标签页优先，其次是最后活跃时间最晚的。列表中标为「重复 · 保留」或「重复 · 将关闭」。
- **关闭重复页 (N)** 一次关闭所有标为「将关闭」的标签页。正在显示、已固定、正在播放声音的副本不会被关闭。
- 关闭时重新计算：页面打开后又被访问、或已跳转到别的地址的标签页，不会按旧判断被关闭。

### 不活跃标签页

**时长只算你在用电脑的时间。** 下面几段时间不计入「多久没访问」：屏幕锁定、电脑休眠、超过 10 分钟没有键盘鼠标操作（从最后一次操作算起）、Chrome 完全退出。这些时段只记开始和结束时间，保存在本机，保留 60 天。周五最后看过的页面，周一回来后只算周五剩下的工作时间。升级之前已经过去的离开时间没有记录，仍按日历时间算。长时间看视频不碰键盘鼠标，也会被当作离开。自动释放内存仍按日历时间 6 小时计算。

参照 Arc 自动归档闲置标签页的做法，但不会自动关闭：列出所有普通窗口中可关闭的标签页，按多久没有切换到分为四组，最久未访问的排在最前：

| 分组 | 未访问时长 |
| --- | --- |
| 48 小时以上 | ≥ 48 小时 |
| 24 – 48 小时 | ≥ 24 且 < 48 小时 |
| 12 – 24 小时 | ≥ 12 且 < 24 小时 |
| 12 小时以内 | < 12 小时 |

- **全部关闭 (N)** 一次关闭超过 12 小时未访问的标签页，即前三组；不包括「12 小时以内」。
- 每组标题右侧 **关闭本组** 只关闭这一组，「12 小时以内」也可以按组关闭。没有标签页的组不显示。
- 弹窗和视图切换上的数字是超过 12 小时未访问的数量。
- 不会列出：各窗口当前显示的标签页、已固定的标签页、正在播放声音的标签页、无痕窗口。
- 关闭时会重新检查：页面打开后又被访问过、已不属于该组时长的标签页不会被关闭；时间推移落入更久分组的仍会关闭。

### 两个视图通用

- 点击行切换到该标签页，每行右侧 × 单独关闭。
- 关闭后底部提示「已关闭 N 个标签页 · 撤销」，8 秒内可撤销，在原窗口原位置重新打开这些地址（不恢复页面内的前进/后退记录；Chrome 的 ⌘ ⇧ T 仍可用）。部分 `chrome://` 内部页面不能由扩展重新打开。

「最后活跃时间」取两者中较晚的一个：Chrome 记录的 `lastAccessed`，以及 Neatab 观察到你离开该标签页的时间（停留在一个标签页上的时长也算活跃）。离开时间保存在 session 存储中，Chrome 重启后只使用 `lastAccessed`。不新增扩展权限。

## 自动释放内存

Chrome 自带的「内存节省」按内存压力决定何时释放标签页，时机不可控。Neatab 按固定规则释放：释放后标签页保留在原位，点开时重新加载。弹窗里的「自动释放内存」开关可以整个关掉。

**什么时候释放：**
- **长时间没访问：** 默认 1 小时没访问就释放，弹窗「释放时机」可选 30 分钟、1 小时、2 小时、6 小时。每 5 分钟检查一次，按日历时间算。
- **Chrome 刚启动时：** Chrome 会在后台把恢复出来的标签页全部加载一遍。这些页面在你点开之前，加载完 3 秒左右就释放。启动后点开过的不受影响。
- **内存紧张时：** 辅助程序把 macOS 的内存压力信号转给扩展。压力警告时释放 15 分钟没访问的标签页，严重时释放 5 分钟没访问的，每分钟最多一次。需要辅助程序在运行。

**哪些不释放：** 正在显示的、正在播放声音的、已经释放过的标签页；关闭时会提示「离开网站？」的页面；无法检查的页面。固定标签页也会释放。

**怎么判断有没有未保存的内容。** 释放前，在页面里模拟一次「关闭」：向页面发一个离开事件，看页面自己会不会要求弹出「离开网站？」确认框，和真正关闭时的判断一致，但不会关闭任何东西。会弹就跳过，不会弹就释放。和 Chrome 一样，你在页面上没有点击或输入过，就不会弹框。`chrome://` 页面、Chrome 网上应用店、3 秒内没有响应的页面无法检查，一律跳过。网站自己在离开时做的事（比如保存草稿）可能会被这次检查触发一次。

弹窗里的说明会显示上次是哪种情况释放的、释放了几个、跳过了几个以及原因。「所有标签页」里已释放的标签页标为「已释放内存」。

## 性能与预览

切换热路径只有：从内存读取最多 7 项 → 绘制原生卡片和全屏截图 → 松键后向 Chrome 发送激活请求。按住时不会激活中间标签页，也不会请求截图、网络或页面重载。无需给每个网页注入脚本。

预览在激活后停稳 900 ms 才尝试生成；同页 15 秒内不重复生成。全局捕获间隔至少 1.1 秒，低于 Chrome 的每秒 2 次限制。每次截图生成两张 JPEG：卡片用的 384 × 240（最大 90 KB），和全屏预览用的宽度最多 1600 px（最大 450 KB）。截图按网址保存在本机的扩展本地存储（`chrome.storage.local`）里，最多 10 组（约 7 MB），超过 7 天的自动删除，所以重启 Chrome 或重新加载扩展后，恢复出来的标签页不用先点开也有预览；同一网址的重复页共用一张。无痕窗口从不截图。关闭「网页预览」会清空内存和本地存储里的全部截图。从来没有显示过的网址（例如在后台新打开、还没点开过的页面）仍然没有截图，显示域名卡片：Chrome 只能截取正在显示的标签页，要截后台页面只能用调试接口，会在每个窗口顶部弹出「正在调试此浏览器」提示条，所以不用。并不是实时视频预览。

**全屏预览。** 按住 Option + Tab 时，选中标签页的大截图铺满当前 Chrome 窗口的网页区域（大小取自 Chrome 报告的网页区域，贴住窗口右下角，左侧抽屉、标签栏和地址栏保持可见；拿不到大小时按窗口宽度铺开），卡片条浮在上面；连按 Tab 时截图跟着换。按住期间只换截图，不激活任何标签页。松开时才激活标签页，截图继续盖在原页面上，直到 Chrome 报告新页面加载完成，再等约 80 ms 让 Chrome 画出新页面，然后淡出 0.12 秒。截图最多停留 1.6 秒。Esc、切到其他应用或激活失败会立刻撤掉截图。

- 截图来自上次停在该页时，不是实时画面；页面之后的变化要等落地后才看得到。
- 没有截图的标签页（`chrome://` 页面、从没显示过的网址、关闭了「网页预览」时）不显示全屏预览，只显示卡片，行为和以前一样。
- 已释放内存的标签页松开后需要重新加载，截图会盖住加载过程，最多 1.6 秒。
- 辅助程序只保存 JPEG 原始数据（最多 7 × 450 KB），只在按住期间解码正在显示的截图，松开后释放。
- 目标标签页在另一个窗口时，截图按当前窗口的网页区域铺开，松开后 Chrome 切到那个窗口。
- Chrome 只报告网页区域的大小，不报告位置，所以默认抽屉在左边。如果抽屉放在右边，或者右侧打开了 Chrome 侧边栏，预览的左右位置会偏。

扩展菜单中的**查看本机性能**会显示本次连接最近 100 次操作的两项 P95：

- 按键处理到原生绘制提交的耗时；不包含显示器扫描输出。
- 松键到 Chrome 激活 API 返回的耗时；不代表网页已完成绘制。

性能是否追平 Arc，需要在同一机器、相同标签页与 Chrome 内存节省配置下实测。当前自动测试不构成与 Arc 的端到端性能对比。Chrome 已休眠的标签页在激活时仍需恢复，其等待时间由 Chrome 和目标网页决定。macOS 的安全输入模式可能限制系统键盘监听。

## 权限与数据

- `tabs`：读取标签标题、地址和访问时间，选择目标标签；关闭不活跃或重复的标签页并在撤销时重新打开。
- `tabGroups`：读取分组的名称和颜色，显示在「所有标签页」里；不修改分组。
- `<all_urls>`：使用 Chrome 的可见标签截图 API；自动释放内存前在页面中运行一次未保存输入检查。没有常驻的网页内容脚本。
- `nativeMessaging`：仅与本机 Neatab 辅助程序通信。
- `storage`：设置保存在本地；最近标签 ID 使用 session 存储。
- `alarms`：每 5 分钟唤醒一次，检查需要释放内存的标签页；每 5 分钟记一次心跳，用来发现休眠和 Chrome 退出的时段。
- `idle`：只读取「正在使用 / 无操作 / 锁屏」这三种状态，用来把离开电脑的时间从不活跃时长里扣掉。不读取输入内容。
- `scripting`：释放前在页面中模拟一次离开，只得到「会不会弹离开提示」这一个结果，不读取或上传内容。
- macOS 辅助功能：接收按键与松键，只在 Chrome 普通窗口前台响应指定组合，不记录输入文本。
- 剪贴板：仅在 Command + Shift + C 触发时，把当前网页链接作为纯文本写入系统剪贴板；不读取或上传原有剪贴板内容。

页面预览保存在本机的扩展本地存储里（最多 10 组、7 天过期，关闭「网页预览」即删除），性能样本只保存在进程内存中。没有后端、账号、分析脚本、远程图标服务或数据上传。不读取 Chrome 浏览历史数据库。

## 开发与验证

构建只依赖 Node.js 和 macOS Xcode Command Line Tools，无 npm 依赖：

```sh
npm test
npm run build
node tests/native-wire.mjs
build/Neatab.app/Contents/MacOS/Neatab --clipboard-self-test
npm run package
```

`npm test` 覆盖 MRU、跨窗、关闭目标、无痕隔离、消息来源验证、截图暂停，以及查询乱序和截图编码期间的设置/导航变化。`build` 自动运行原生状态机与帧协议检查。`tests/native-wire.mjs` 启动真实 host，测试分片 UTF-8 管道、快照更新、回复与正常退出，不启用切换或申请权限；AppKit 启动需要 macOS 图形会话。

复制链接测试覆盖最新前台标签、长链接、参数/锚点保留、无痕隔离和查询期间切换窗口。原生 `--clipboard-self-test` 使用独立测试剪贴板验证真实 AppKit 写入，不读取或覆盖用户的系统剪贴板。

`node scripts/preview-server.mjs` 启动本机虚构数据 UI 预览（端口 4177），不连接真实标签页。原生静态布局可用：

```sh
build/Neatab.app/Contents/MacOS/Neatab --render-fixture build/neatab-preview-light.png
build/Neatab.app/Contents/MacOS/Neatab --render-fixture build/neatab-preview-dark.png --dark
```

安装后的真实验收清单见 `VALIDATION.md`。只有真实浏览器验收和性能对比完成后，才能宣称全目标完成。

## 实现依据

Chrome Commands API 不接受 Tab 作为声明式扩展快捷键，且扩展无法在所有浏览器 UI 上获取修饰键松开事件，所以采用原生 host 完整接管 Option + Tab，而没有用其他快捷键替代。参考：[Commands API](https://developer.chrome.com/docs/extensions/reference/api/commands)、[Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)、[Tabs API](https://developer.chrome.com/docs/extensions/reference/api/tabs)。
